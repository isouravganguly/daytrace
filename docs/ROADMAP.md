# Hold This Thought — roadmap

Last updated: 2026-07-26

## Near-term product goal

Make the app feel useful every day, even before it becomes “smart”. The MVP should be a trustworthy capture surface with clean retrieval.

## Next best slices

### 1. Capture UI polish

Why: the app’s first impression is the product.

Do next:

- Replace the circular Speak CTA with a modern full-width hold-to-speak control.
- Use clear states:
  - idle: “Hold to speak”.
  - listening: “Listening… release to save transcript”.
  - processing permission: “Allow microphone”.
- Keep button shapes consistent:
  - primary actions: 48dp height, 12dp radius.
  - chips: pill shape.
  - cards: 8dp radius.
- Consider adding subtle haptic feedback on press/release.

### 2. Better thought sections

Why: todos currently have a home, but thoughts should also feel intentionally stored.

Do next:

- Keep drawer destinations:
  - Thoughts.
  - Notes.
  - Todos.
  - Search.
- Add a small “recent thoughts” preview only if it does not clutter the capture screen.
- Add metadata labels that are useful but quiet:
  - kind.
  - space.
  - created date.

### 3. Hybrid search

Why: search is the memory feature.

Do next:

- Keep instant local literal search.
- Add remote semantic search through the `thought-machine` Edge Function.
- Merge semantic and local results.
- Add result source/debug information only in a hidden developer/settings area.

### 4. Todo lifecycle

Why: once todos exist, they need basic completion.

Do next:

- Add complete/uncomplete.
- Hide completed todos by default.
- Add an optional completed section later.
- Avoid turning the app into a heavy todo manager.

### 5. Reflection and learning loop

Why: the long-term product is not just storage; it should help the user improve.

Possible features:

- “What did I keep thinking about this week?”
- “Remind me of learnings I keep forgetting.”
- “Turn recent thoughts into principles.”
- “What’s one action from my recent thoughts?”
- Weekly private digest.
- Repetition/reminder system for learnings.

### 6. Modular auth

Why: anonymous auth is good for MVP, but long-term continuity needs account recovery.

Options:

- Keep anonymous-first onboarding.
- Add magic link or passkey later.
- Allow linking anonymous user to permanent auth.
- Avoid forced signup before first capture if possible.

### 7. Data safety and export

Why: personal thoughts need user trust.

Do next:

- Add export as Markdown or JSON.
- Add local backup/import.
- Add delete thought.
- Add “delete all cloud data” only with careful confirmation.

## Longer-term ideas

- Tags generated by AI but editable by the user.
- People/project/topic extraction.
- Daily review mode.
- Calendar/reminder integration.
- Home-screen quick capture widget.
- Wear/voice assistant capture.
- End-to-end encryption research for cloud storage.
- Offline speech model improvements.

## Product risks to avoid

- Do not make capture slower to make AI smarter.
- Do not show sync failures on the capture screen.
- Do not overbuild todo management.
- Do not make the user classify every thought manually.
- Do not ship provider API keys in the Android APK.
- Do not rely on a consumer AI login/subscription for production model calls.
